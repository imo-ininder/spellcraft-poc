## 1. Game Concept

這是一款以即時 PvE 戰鬥與 Boss 戰為核心的魔法動作遊戲。

玩家可以使用普通攻擊與基礎法術維持戰鬥節奏，也可以進入專注狀態，讓世界時間大幅減慢，並透過符文輸入沿著預先設計的法術圖譜改變目前準備施放的法術。

玩家不只是選擇預先設定好的技能，而是在戰鬥過程中決定：

- 現在是否值得消耗專注值。
- 應該將法術演化成什麼形態。
- 是否繼續演化，或立即施放目前的法術。
- 面對 Boss 的不同動作與戰場情況，哪一種法術行為最合適。

核心體驗：在敵人的壓力下判讀戰況，透過符文改變法術，並自行決定施法時機。

## 2. Core Design Pillars

### 2.1 即時戰鬥判斷
玩家必須閱讀 Boss 的行為與戰場狀態，選擇合適的法術形態，而不是永遠使用傷害最高的固定連招。

### 2.2 施法本身就是操作
玩家不是打開技能選單選擇法術，而是在專注狀態中輸入符文，逐步改變目前的法術。

### 2.3 法術演化必須改變戰術
法術的衍生形態應該具有不同的行為與用途，而不只是增加傷害、射程或持續時間。

### 2.4 時間與資源形成取捨
專注狀態讓玩家有更多時間思考與輸入，但會持續消耗專注值。玩家需要判斷何時進入、演化到什麼程度，以及何時施放。

### 2.5 法術圖譜可以學習與精通
法術的節點與轉換路徑由設計者預先定義。玩家透過理解與練習掌握常用路徑，而不是依賴隨機生成法術。

## 3. Combat Controls

### 3.1 基本操作

| 操作 | 功能 |
|---|---|
| 左鍵（LMB） | 一般狀態下進行普通攻擊或蓄力火球；專注狀態下施放目前的法術 |
| 右鍵（RMB） | 進入或退出專注狀態 |
| 符文輸入按鍵 | 專注狀態下輸入符文，改變目前的法術節點 |
| WASD | 移動角色 |
| Space | 閃避／衝刺（暫定） |

### 3.2 左鍵：主要動作鍵

左鍵是整套戰鬥系統的主要動作鍵，但會根據目前狀態執行不同功能。

**一般狀態：**
- 普通攻擊三連段。
- 蓄力火球，提供直接且簡單的遠程攻擊。

**專注狀態：**
- 點擊左鍵，施放目前法術圖譜節點對應的法術。
- 任何有效節點都可以作為施法終點。

這樣可以讓普攻、基礎法術與符文施法共用主要動作鍵，同時保留各自的操作深度。

### 3.3 右鍵：專注狀態

右鍵用來進入或退出專注狀態。

**進入後：**
- 世界時間大幅減慢，但不會完全停止。
- 專注值開始持續消耗。
- 玩家可以輸入符文並演化目前的法術。
- 玩家可以隨時透過左鍵施放目前的有效法術。

**退出後：**
- 世界恢復正常時間流速。
- 停止消耗專注值。
- 尚未施放的法術如何處理，仍待確認。

右鍵究竟採用「點擊切換」還是「按住維持」，尚未定案。原型階段應先測試哪一種更適合實際戰鬥節奏。

## 4. Focus Mode & Bullet Time

### 4.1 專注狀態的核心機制

專注狀態不是固定持續數秒的技能，而是由專注值決定玩家可以使用多久的戰術思考與施法時間。

玩家進入專注狀態後，世界進入 Bullet Time，並持續消耗專注值。玩家可以：

- 只輸入一個符文，快速施放簡單的衍生法術。
- 輸入多個符文，嘗試抵達更深層的法術節點。
- 在專注值耗盡之前，隨時施放目前的法術。
- 判斷是否值得繼續消耗專注值，以換取更適合當前戰況的法術。

### 4.2 專注值

| 項目 | 設計方向 |
|---|---|
| 資源形式 | 連續數值 |
| 消耗方式 | 專注狀態持續消耗 |
| 最大值 | 暫定100 |
| 消耗速度 | 待定，原型階段先測試固定消耗速率 |
| 恢復方式 | 隨時間回復 |
| 耗盡時的處理 | 退出專注模式並施放目前的有效法術 |
| 是否可隨時退出 | 可以，退出時施放目前所在的法術節點 |

### 4.3 Bullet Time 的設計目的

Bullet Time 不應該讓玩家完全脫離戰鬥，而是提供一個有限的決策空間。

即使世界時間減慢，玩家仍需要：
- 判斷 Boss 正在準備什麼動作。
- 選擇法術演化方向。
- 控制符文輸入的速度與順序。
- 決定是否繼續投入資源。
- 選擇施放時機。

世界減速比例、敵人動作減速幅度，以及專注狀態能否完全免疫受擊，都需要透過原型驗證。

## 5. Spell Graph System

### 5.1 基本概念

每種元素都有一張預先設計的法術圖譜。圖譜由節點與轉換路徑組成：

- **節點（Node）**：一種完整可施放的法術，或可繼續演化的法術狀態。
- **路徑（Transition）**：透過指定符文，從目前節點轉換至另一個節點。
- **符文（Rune）**：用於觸發特定節點轉換的輸入。

節點可以同時是完整法術與中間狀態。只要該節點允許施放，玩家就可以直接釋放，不必繼續演化。

### 5.2 範例法術圖譜

以火元素為例：

```
                ┌── 持續（Persist）──> 持續燃燒區域
                │                          │
基礎火球 ────────┤                          └── 前進（Advance）
                │                                   │
                │                                   ▼
                │                              向前推進的
                │                              持續火焰軌跡
                │
                └── 其他符文路徑 ──> 其他法術形態
```

上述圖譜僅為概念示例，實際節點、符文與路徑尚未定案。

### 5.3 法術演化規則

1. 玩家從目前的法術節點開始。
2. 輸入符文，沿著有效路徑轉換到另一個節點。
3. 玩家可以繼續輸入符文，探索更深層的衍生法術。
4. 玩家可以隨時施放目前的有效節點。
5. 若目前節點存在反向路徑，玩家可以透過相應符文返回之前的節點。並非所有轉換都必須能夠反向操作。

法術圖譜是由設計者預先定義的，不是根據任意符文組合即時生成全新的法術。

### 5.4 法術演化的設計原則

不同衍生法術必須在戰術用途上有所區別。例如：

- **直接火球**：快速攻擊單一目標。
- **持續燃燒區域**：控制特定位置，限制敵人的行動空間。
- **向前推進的火焰軌跡**：覆蓋路徑上的敵人，或對移動中的目標施加壓力。

如果兩個節點只是傷害數字不同，而實際使用方式完全相同，就需要重新考慮它們是否值得獨立存在。

## 6. Elements & Specialization

不同元素擁有獨立的法術圖譜，並代表不同的戰鬥風格。可能的元素包括：

- 火
- 冰
- 雷電

元素不應該只是傷害類型的差異，也可以透過法術行為形成不同的戰鬥策略。例如，某種元素可能擅長區域控制，另一種可能擅長快速攻擊或限制敵人行動。具體定位仍待設計。

玩家可以專精於一種元素，深入學習其法術路徑，不必一次掌握所有元素的完整圖譜。

元素數量、解鎖方式與是否能在戰鬥中切換元素，均待確認。

## 7. Basic Attacks

普通攻擊與基礎法術是玩家在不進入專注狀態時的主要戰鬥手段。

### 7.1 普通攻擊
- 使用左鍵觸發。
- 具備三連段攻擊。
- 不需要進入專注狀態。
- 具體攻擊速度、傷害、連段判定與移動限制待定。

### 7.2 蓄力火球
- 使用左鍵蓄力並施放。
- 不需要進入專注狀態。
- 提供簡單直接的遠程攻擊方式。
- 蓄力時間、射程、傷害與移動限制待定。

### 7.3 與符文施法的關係

基本攻擊不應該只是無用的過渡動作，也不應該強到讓複雜的符文施法失去意義。它們的定位是提供穩定、直接的戰鬥手段；符文施法則提供更高的戰術彈性與更複雜的法術行為。玩家需要在兩者之間建立自然的戰鬥節奏。

## 8. Equipment System

裝備系統預計納入遊戲，但具體規則尚未定案。設計方向是讓裝備影響玩家的戰鬥風格，而不是單純提供不斷膨脹的數值。裝備系統應該服務於核心戰鬥，而不是成為取代玩家操作與判斷的主要成長來源。

## 9. Player Skill & Mastery

玩家的技巧主要來自以下幾個方面：

### 9.1 戰鬥判斷
讀懂 Boss 的攻擊模式、位置與戰場狀態，判斷目前需要哪一種法術行為。

### 9.2 法術圖譜熟悉度
記住常用的節點與符文路徑，減少在專注狀態中尋找方向的時間。

### 9.3 輸入效率
在專注值有限的情況下，以更少的輸入抵達理想節點。

### 9.4 施放時機
知道什麼時候應該停止演化，立即施放目前的法術，而不是一味追求更深層的節點。

### 9.5 資源管理
在基本攻擊與專注施法之間建立節奏，避免將專注值全部消耗在低價值的施法上。

## 10. Prototype Scope

第一個原型的目的不是建立完整遊戲，而是驗證核心戰鬥循環是否有趣、清晰且能夠精通。

### 10.1 必須實作
- 玩家角色與一個簡單的 Boss 或訓練目標。
- 一種元素：火。
- 一個基礎法術，以及至少4種戰術用途不同的衍生法術。
- 法術節點與預先定義的符文轉換路徑。
- 右鍵進入與退出專注狀態。
- Bullet Time 與持續消耗的專注值。
- 透過符文輸入演化法術。
- 在任何有效節點施放法術。
- 專注值耗盡時的暫定處理方式。
- 普通攻擊三連段。
- 蓄力火球。
- 能清楚顯示目前法術節點的基本 UI 與視覺效果。

### 10.2 暫時不需要
- 多種元素與大量法術。
- 完整的裝備、掉落與 Build 系統。
- 大量 Boss 與關卡。
- 任意組合符文、即時生成法術的系統。
- 複雜的成長系統。
- 完整的技能解鎖與長期養成流程。

### 10.3 原型要回答的問題
- 玩家是否享受在有限專注值下演化法術的過程？
- Bullet Time 是否提供思考空間，同時仍保留戰鬥壓力？
- 不同法術形態是否真的改變玩家的戰術選擇？
- 玩家是否能逐漸熟悉法術圖譜，而不是被迫背誦大量路徑？
- 玩家是否會自然地在普通攻擊與符文施法之間切換？
- 玩家是否會主動選擇提前施放，而不是總想把法術演化到最深層？

## 11. Risks & Design Principles

### 11.1 主要風險
- **Bullet Time 過於安全**：如果玩家能頻繁進入專注狀態，戰鬥可能失去壓力。
- **圖譜過於複雜**：如果玩家必須記住太多路徑，操作可能變成背誦考試。
- **施法過於緩慢**：如果每次施法都必須經過太多輸入，玩家可能不願使用系統。
- **基本攻擊失去定位**：普通攻擊太弱會迫使玩家一直施法；太強則會讓法術演化變得多餘。
- **專注值缺乏取捨**：如果資源太容易恢復，或消耗完全不影響決策，系統就無法形成有意義的限制。

### 11.2 核心原則
- 符文輸入必須形成有意義的即時決策，而不只是增加施法延遲。
- 衍生法術必須改變行為或戰術用途，而不只是提升數值。
- 玩家可以施放任何有效節點，不必完成整條路徑。
- 法術圖譜由設計者預先定義，玩家負責探索與精通。
- 玩家只需精通部分常用路徑，就應該能有效戰鬥。
- 基本攻擊提供穩定輸出，符文施法提供更深的戰術選擇。
- 專注值應該形成取捨，而不是單純限制玩家操作的時間。
- 裝備與成長系統應該服務於核心戰鬥。
- 先驗證最小可玩原型，再擴展內容。

## 12. Open Questions

以下項目尚未定案，應在原型測試或後續設計中逐步確認。

**專注狀態**
- 專注值最大值是多少？
- 專注值以固定速率消耗，還是依照法術演化深度改變？
- 專注值透過時間自動恢復、攻擊命中或其他方式恢復？
- 手動退出專注狀態時，尚未施放的法術如何處理？
- 專注值耗盡時，自動施放是否為最合適的行為？
- 專注狀態下玩家可以移動、閃避或受到攻擊嗎？

**符文輸入**
- 符文使用方向鍵、按鍵序列，還是其他輸入方式？
- 如何清楚呈現目前節點與可選擇的轉換？
- 返回先前節點是否透過反向符文，還是獨立操作？
- 如何讓玩家學習圖譜，又不需要在戰鬥中閱讀複雜 UI？

**戰鬥與法術**
- 普通攻擊與符文法術之間如何建立有效的戰鬥節奏？
- Boss 的哪些行為會讓不同法術形態產生不同價值？
- 如何避免玩家找到一條固定的最高效率路徑後，就不再考慮其他選擇？

**裝備與成長**
- 裝備會改變數值、法術行為、專注資源，還是多者兼有？
- 玩家如何解鎖新的元素與法術路徑？
- 如何在長期成長與操作技巧之間取得平衡？

## 13. One-Sentence Summary

一款即時 PvE 魔法動作遊戲：玩家以普通攻擊維持戰鬥節奏，並在需要戰術決策時透過右鍵進入專注狀態，以持續消耗的專注值換取 Bullet Time，再使用符文沿預先設計的法術圖譜演化法術，最後由左鍵決定何時施放。

# Rune Input System

## 1. 符文輸入方式

目前預計設計 9 種符文，透過方向鍵序列觸發。

| 編號 | 輸入序列 | 暫定分類 |
|---|---|---|
| R1 | 上 → 上 | 同方向重複 |
| R2 | 右 → 右 | 同方向重複 |
| R3 | 左 → 左 | 同方向重複 |
| R4 | 下 → 下 | 同方向重複 |
| R5 | 上 → 下 | 垂直反向 |
| R6 | 下 → 上 | 垂直反向 |
| R7 | 左 → 右 | 水平反向 |
| R8 | 右 → 左 | 水平反向 |
| R9 | 上 → 右 → 下 → 左 | 四方向序列 |

以上分類僅用於整理輸入方式，尚不代表各符文的實際功能或設計語意。

## 2. 設計原則

- 每種符文都有固定的輸入序列。
- 符文用於觸發法術圖譜中的節點轉換。
- 不同符文可以在不同法術節點產生不同的轉換結果。
- 符文名稱、視覺表現、法術效果與可用路徑尚未定案。
- 輸入序列需要在實際戰鬥中容易辨識與操作，避免玩家因輸入辨識而頻繁中斷思考。

## 3. 待確認事項

- 方向鍵輸入需要在多短的時間內完成？
- 每次輸入完成後，是否立即觸發符文？
- 不完整或錯誤的輸入序列如何處理？
- 四方向序列是否與兩方向序列使用相同的輸入判定規則？
- 是否允許玩家在施法圖譜中反覆使用同一種符文？

## 附註：與現有專案的對應關係（2026-10-13，agent 補充）

這份文件是使用者原樣提供的規劃書（僅修正 §9.5 一處明顯的複製貼上重複字句），不是這個專案既有系統的描述。以下記錄現有程式碼哪些部分預期可以沿用、哪些需要重新設計，給之後接手實作的人（或 agent）快速定位：

- **符文輸入判定**（`Rune Input System` §1-2）：現有 `Player.gd` 的 `_handle_combo_key()`／`combo_buffer`／`pending_combo`／`COMBO_MAX_GAP` 前綴比對機制，技術上就是「在時間窗口內累積方向鍵、判斷還有沒有更長的合法序列」這套邏輯，R1-R9 的序列設計跟現有 `GameState.ARCANE_FEATS` 的 UU/DD/UDU 同構。但現有邏輯是「序列完成→套用一個全局數值修飾符」，這份新規劃要的是「序列完成→沿圖譜邊走到另一個具體節點」，判定邏輯可以搬，觸發後的行為要整個重寫。
- **法術實作架構**（§5 Spell Graph System）：現有 `Spell`/`SpellDelivery`/`SpellEffect`/`ProjectileImpact` 的三層關注點分離（見 `docs/SPELL_SYSTEM.md`）適合拿來實作圖譜節點本身的具體行為（例如「向前推進的持續火焰軌跡」可能是 `ProjectileDelivery` 配新的 impact），但「一把法術一份 `.tres`、玩家裝備6把」的資料模型要換成「一張元素圖譜、節點用符文連接」，不是直接複用。
- **Bullet Time／專注值**（§4）：現有最接近的參考點是法術輪盤開啟時的 `Engine.time_scale = 0.25`（見 `Player._open_wheel()`），但那是選單暫停，不是戰鬥中持續消耗的資源機制，專注值系統要新寫。
- **完全沒有、要新寫的**：普通攻擊三連段、蓄力火球（現有玩家沒有任何近戰/非吟唱攻擊手段）、專注值資源本身、法術圖譜資料結構。
- **跟這次設計無關、可以直接沿用的獨立系統**：`GroundProjection`（橢圓壓扁）、`MagicFX`（粒子特效）、`Arena` 場地結構（但原本「玩家/boss 物理隔絕」的三環設計前提已經不成立，見 `scripts/core/Arena.gd` 開頭註解）、`HealthOrb`/`DeathScreen` UI、`GameState` autoload、Dash（§3.1 的「Space 閃避／衝刺」跟現有實作幾乎一樣）、玩家角色的 `AnimatedSprite2D`／`PlayerSpriteAnimator.gd`（見 `docs/ROADMAP.md` §2.1a）。
- **已經刪除**：原本的 Demo boss（`scripts/entities/boss/`、`docs/BOSS_DESIGN.md`）2026-10-13 整個移除，之後要照這份新規劃重新設計。
