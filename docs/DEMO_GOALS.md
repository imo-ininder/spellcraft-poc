# Demo 目標

> 定位：自己/小圈子試玩。範圍涵蓋法術系統架構、法術配置與切換、基礎美術與音樂、完整的 Demo 流程UI。不是放大版的 PoC，是一個能從頭玩到結束、畫面與操作都完整的獨立版本。

---

## 1. 驗收標準

玩家在大廳場景於固定 6 格法術欄位預算內自由配置法術（攻擊／buff／位移，不同法術佔用不同格數），超魔專長本身固定全開不需配置，進入戰鬥後：

- 用「吟唱中打超魔專長」機制搭配「法術切換輪盤（子彈時間，支援任意把數）」與怪物周旋。
- 若裝備範圍型攻擊或長距離位移類法術，施放時真正暫停並切換到選點視角；若未裝備位移類法術，空白鍵是不經選點、直接朝滑鼠方向衝刺的基礎 Dash。
- 打倒怪物或被打死都有明確結束畫面，可重新開始。

整個流程（大廳→戰鬥→結算→重來）有完整 UI 銜接，視覺與音效使用美術/音樂資源而非程式繪圖，法術系統使用資料驅動架構。

## 2. 法術系統架構

### 2.1 三層關注點分離

| 層級 | 內容 | 存放位置 |
|---|---|---|
| `Spell` | 法術的靜態資料：`id`／`display_name`／`icon`／`cast_time`／`max_range`／`delivery`／`base_effects` | Resource（`.tres`） |
| `SpellDelivery` | 法術怎麼發出去、怎麼判定命中 | Resource，少量可重用策略 |
| `SpellEffect` | 命中後發生什麼事，可疊加 | Resource，少量可重用策略 |
| 執行時狀態 | CD 倒數、吟唱進度、生效中的 buff 清單 | 角色節點本身，絕不放在 Resource 上 |

Resource 是共享引用，不是值型別：兩個角色裝備同一個 `.tres` 資源時，若把運行時狀態存在 Resource 上，狀態會互相污染。CD、buff、吟唱進度一律存在角色節點身上。

### 2.2 Delivery（三種）

- **`ProjectileDelivery`**：直線投射物，依 `max_range` 判定最遠飛行距離（累計實際飛行距離並比對，不用時間模擬）。對應攻擊類法術。
- **`SelfDelivery`**：效果直接套用在施法者自己身上，無命中判定。對應 buff 類法術。
- **`AoETargetingDelivery`**：施放時暫停遊戲、切換到可視範圍更大的選點視角，顯示跟隨滑鼠的指示圈（受 `max_range` 限制，超出範圍時圈變灰/鎖在邊界），確認輸入後恢復遊戲並執行收尾動作。收尾動作依用途二選一：
  - 範圍型攻擊法術：對選定點套用傷害類 `SpellEffect`。
  - 長距離位移法術：把施法者座標移動到選定點。

### 2.3 Effect（依類別至少各一個）

- 攻擊：`DamageEffect`（瞬發）。
- Buff：至少一個 `apply_mode = DURATION` 的效果（例如 `CastSpeedBuffEffect`），需要角色身上維護一份「目前生效中的 buff」清單；持續性效果的倒數計時狀態存在角色身上建立的運行時物件中，不存在 `SpellEffect` 資源本身。
- 位移：透過 `AoETargetingDelivery` 選點後直接移動施法者座標，`base_effects` 可為空陣列。

### 2.4 基礎 Dash 與位移類法術的分工

空白鍵的行為由「是否裝備位移類法術」決定：

- **未裝備位移法術**：觸發角色身上寫死的基礎 Dash——短時間內朝「目前移動方向」（WASD，不是滑鼠方向，衝刺跟瞄準是兩件事）高速衝刺一段固定距離（不是瞬移/Blink，衝刺過程中會自然貼牆滑行、碰到牆就停下，不是瞬間跳到終點），不經過任何選點流程，不走 `Spell`/`SpellDelivery` 架構，不佔用法術欄位，永遠可用。實作細節見 `DESIGN.md` §4.6。
- **已裝備位移法術**：觸發該法術，走 `AoETargetingDelivery` 的暫停選點流程。

兩套邏輯互斥，由裝備狀態在輸入處理最前端分流，不混寫在一起。

### 2.5 角色資料結構與法術格系統（已實作，見 `DESIGN.md` §4.7）

**配置的單位是法術，不是超魔專長**（見 §4 的澄清）。角色固定 6 格法術欄位（`GameState.TOTAL_SLOTS`），每把法術各自佔用不同格數（`Spell.slot_cost`：火球術3／力場波2／雷電箭1），玩家在大廳場景（`scenes/Lobby.tscn`）勾選要帶上戰場的法術，超過格數預算時直接拒絕勾選並反紅提示。不包含職業、升級、屬性成長——角色系統在這次範圍內僅作為法術配置的持有者。

跨場景傳遞用新增的 autoload 單例 `GameState`（`scripts/state/GameState.gd`）：維護法術總表（`CATALOG`）、`equipped_spells`（大廳寫入、戰鬥場景讀取），空清單時 fallback 成全部法術，讓「不經大廳直接測試戰鬥場景」的工作流程不受影響。

## 3. 法術切換輪盤

- 按住 Ctrl 彈出輪盤 UI，顯示已裝備的法術（**數量不固定為3**，依大廳配置結果而定，見 §2.5——輪盤角度公式本來就支援任意把數，已實作並驗證）。
- 彈出時 `Engine.time_scale` 降至約 0.25（實測後調整），放開/選定後恢復 1.0。這是子彈時間，不是暫停：怪物與場上一切持續運作，只是變慢。
- 滑鼠移到對應法術圖示上即選中，放開 Ctrl 或點擊確認即切換為當前使用中的法術。
- 輪盤開啟時玩家唯一能做的操作是選法術，不會同時吟唱，不需處理符紋計時窗口與 `time_scale` 的同步。
- 輪盤的子彈時間與 `AoETargetingDelivery` 的真正暫停是兩種機制，服務不同情境：輪盤用於「決定下一個要用的法術」；真正暫停用於「選一個施放/傳送的地點」。

## 4. 超魔專長（原「符紋」，已重新命名，見 `DESIGN.md` §4.7）

延續 PoC 的判定邏輯（前綴匹配＋pending 機制，`COMBO_MAX_GAP` 時間窗口），**範圍已確定調整**：

- 超魔專長是角色永久學會的被動能力，**不綁定特定法術**，吟唱任何法術時都能打出同一組按鍵序列觸發同一組效果——有沒有實際作用，取決於目前裝備的法術吃不吃得到這個效果類型（例如傷害加成對任何攻擊法術都通用）。
- **大廳不配置超魔專長**，真正要在大廳配置的是法術本身（見 §2.5）。Demo 階段超魔專長固定全部解鎖，不做學習/解鎖介面。
- 不包含超魔專長掉落、解鎖、強化（解放）系統——這些留給正式版。
- `SPELL_SYSTEM.md` §9 提的 capability 相容性機制（過濾「這把法術吃不到的專長」）這次不做，因為目前所有專長效果（傷害加成、吟唱速度）都是通用的，沒有需要過濾的實例。

## 5. 戰鬥結算

- 玩家具備真實 HP／`max_hp`，被怪物攻擊時實際扣血；HP 歸零觸發失敗狀態。
- 怪物 HP 歸零時播放死亡表現，停止 AI，觸發勝利狀態（不再像 PoC 一樣重置滿血重複測試）。
- 數值（怪物傷害、攻擊循環間隔、玩家 `max_hp`）需實測調整，使戰鬥時長落在合理範圍，不是秒勝秒敗。

## 6. 美術與音樂

- 角色、怪物、投射物、地板改用免費可商用（CC0 或同等授權）的 2D 素材，調性延續 Q 版鮮豔、誇張比例的奇幻風格；避免寫實/黑暗調性。
- `Player.tscn`／`TargetDummy.tscn`／`SpellProjectile.tscn` 的 `_draw()` 程式繪圖移除，改用 `Sprite2D`／`AnimatedSprite2D`。
- 地板改用 `TileMap` 搭配真實磚塊貼圖，牆體碰撞邏輯不變。
- 粒子特效（`MagicFX.gd` 的 `spawn_burst()`／`make_sparkle_trail()`）保留現有程式邏輯與呼叫介面，內部補上美術提供的粒子貼圖（`texture` 屬性），不再是純色圓點。
- 音效：吟唱、符紋成功/失敗、法術發射/命中、怪物跳躍/落地。音樂：戰鬥、勝利、失敗。全部使用免費授權素材。
- 色彩分工延續既有慣例：傷害＝紅、爆炸/範圍＝橘、強化/爆發＝粉紫或金黃、吟唱速度加快＝青、吟唱速度減慢＝藍紫；吟唱中＝紫、符紋成功＝綠閃、符紋失敗＝紅閃、受擊＝橘閃。美術資源設計時沿用，保持辨識度一致。（穿透、投射物彈速機制都已移除，不再需要穿透色/彈速色——吟唱速度跟投射物彈速是兩個不同概念，不要混在一起）

## 7. UI 規格

Demo 需要完整銜接以下畫面，缺一不可：

### 7.1 主選單
- 開始／退出。進入後直接到大廳。

### 7.2 大廳（已實作，見 `DESIGN.md` §4.7）
- 法術清單（目前純文字列表＋CheckButton，尚未做場景化的角色站位視覺）：列出法術總表（`GameState.CATALOG`），每個選項顯示法術名稱與佔格數，勾選即裝備。
- 格數預算顯示：「已用 X / 6 格」，超過預算時這次勾選直接被拒絕並反紅閃一下彈回未勾選狀態，不是「允許超選但出發按鈕變灰」。
- 「出發」按鈕：將目前勾選結果寫入 `GameState.equipped_spells`，切換到 `Main.tscn`。
- **尚未做**：角色站在場景裡的視覺呈現（§7.2 原本設想的「有小場景感的大廳」），目前是純 UI 列表，功能完整但沒有場景美術。

### 7.3 戰鬥 HUD（持續顯示）
- 玩家 HP 條。
- 當前使用中法術圖示＋右鍵瞬發 CD 進度。
- 吟唱時的進度條與超魔專長輸入即時回饋（沿用 PoC 已有機制：成功/失敗提示、已疊加專長圖示列）。
- 怪物 HP 條。

### 7.4 法術切換輪盤（疊加於戰鬥畫面，已實作）
- 按住 Ctrl 顯示，已裝備的法術圖示依數量等分環形排列（支援任意把數，不限3個），滑鼠移到圖示上高亮，放開/點擊確認切換。

### 7.5 範圍/位移選點視角（疊加於戰鬥畫面，暫停時顯示）
- 跟隨滑鼠移動的指示圈，受 `max_range` 限制：超出範圍時圈變灰或鎖在邊界，提示不可選取。
- 確認鍵／取消鍵的提示文字。

### 7.6 結算畫面
- 勝利／失敗兩種版本，顯示結果文字。
- 「重新開始」：重置玩家 HP／位置、怪物 HP／狀態、清除場上殘留投射物，回到戰鬥開始狀態（不重新配置法術，沿用大廳設定；或回大廳重新配置，二選一，依試玩需求決定）。

## 8. 明確排除

- 掉落／裝備系統。
- 職業、角色養成、升級。
- 多隻怪物／多種怪物攻擊模式（維持單一怪物、單一跳躍落地攻擊模式）。
- 存檔、多關卡。
- Mana 系統。
- 超魔專長掉落、解鎖、強化（解放）系統（Demo 階段固定全開，見 §4）。
- `SPELL_SYSTEM.md` §9 的 capability 相容性過濾機制（見 §4 最後一點，目前沒有需要過濾的實例）。

## 9. 風險

1. **Buff 的 duration／狀態清單機制**是新增工作量最大的部分，需要設計角色身上「目前生效中 buff」的最小可用清單與疊加/覆蓋規則。
2. **`AoETargetingDelivery` 的暫停／選點／鏡頭切換**需同時支援「套用傷害效果」與「移動施法者」兩種收尾動作，實作時避免只照顧其中一種用途。
3. **基礎 Dash 與位移類法術必須在輸入處理最前端分流**，兩套邏輯不可混寫。
4. **美術資源風格一致性**：不同作者的免費素材拼裝容易風格不統一，挑選階段需做風格比對，不是找到就用。
5. **架構先行的開發成本**：法術系統先建好 `Spell`/`SpellDelivery`(x3)/`SpellEffect`(含duration機制) 再產出內容，比直接堆 if/elif 慢，但換取之後法術持續擴充時不需要重寫。
