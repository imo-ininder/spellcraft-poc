# Fire Prototype — Game Design Document

> 使用者提供的第一個可動手做的原型規格書，具體到符文語意/法術圖譜/數值的程度，是 `docs/GDD.md`（抽象方向）跟 `docs/DEMO_PLAN.md`（這份文件拆解出來的實際開發 phase）之間的橋樑。內容原樣保留，只修正了兩處確認過的錯誤：(1) §5.1/§5.3 對「火焰撤離」路徑來源的內部矛盾——表格寫「火焰地面→左左」，ASCII 圖畫的是「火焰護盾→左左」，2026-10-13 跟使用者確認照表格版本，下面 §5.3 的圖已經改成一致版本；(2) 「火焰撒罐」統一成「火焰撤離」（顯然是打字誤繕，§5.1 表格行名跟 §6.4 標題都是「撤離」，只有 ASCII 圖跟 §5.1 路徑欄位的次要提及打成「撒罐」）。

Version: 0.4
Scope: First playable combat prototype
Element: Fire
Primary Goal: Validate rune-based spell evolution in real-time combat.

## 1. Prototype Objective

建立一個最小可玩的火系魔法戰鬥原型，驗證以下核心問題：

- 玩家能否在戰鬥中直覺地使用符文改變法術？
- 不同法術節點是否帶來真正不同的戰術選擇？
- 右鍵進入專注、左鍵施法的操作方式是否自然？
- 持續消耗的專注值是否形成有意義的資源取捨？
- 玩家是否會根據敵人行為，選擇不同的法術演化路徑？

Prototype 暫時不追求完整內容量、長期成長或裝備系統，只驗證核心戰鬥循環。

## 2. Core Gameplay Loop

```
一般戰鬥
    │
    ├── 左鍵：普通攻擊三連段
    │
    └── 左鍵：蓄力火球
              │
              ▼
       判斷當前戰況
              │
              ▼
       右鍵進入專注
              │
       世界時間減慢
       專注值持續消耗
              │
              ▼
       輸入方向符文
              │
       沿火系法術圖譜
       切換目前法術節點
              │
              ▼
       左鍵施放目前法術
              │
              ▼
       結束專注並恢復正常時間
              │
              ▼
          繼續戰鬥
```

玩家不需要完成整條法術路徑才能施法。只要目前位於有效節點，就能立即釋放該節點的法術。

## 3. Controls

| 操作 | 一般狀態 | 專注狀態 |
|---|---|---|
| 左鍵 | 普通攻擊／蓄力火球 | 施放目前法術 |
| 右鍵 | 進入專注 | 退出專注 |
| 上下左右 | 一般移動 | 符文輸入 |
| Space | 閃避／衝刺 | 暫定沿用，待測試 |

操作規則：
- 右鍵控制專注狀態的進入與退出。
- 進入專注後，世界時間減慢，專注值開始持續消耗。
- 方向輸入用於切換法術節點。
- 左鍵施放目前節點對應的法術。
- 施法後退出專注，恢復正常時間。
- 專注值耗盡時，第一版暫定自動施放目前法術。
- 若符文輸入不符合目前節點的有效路徑，不進行節點轉換。

最後三項是 Prototype 的初始規則，仍可依實際操作感調整。

## 4. Rune System

### 4.1 九種共通符文

所有元素共用相同的符文語意。第一個 Prototype 只使用火系圖譜驗證這套規則。

| 輸入序列 | 語意 | Prototype 狀態 |
|---|---|---|
| 上上 | 提升／強化 | 使用 |
| 下下 | 穩定 | 使用 |
| 右右 | 前進 | 使用 |
| 左左 | 自身／後退 | 使用 |
| 左右 | 擴展 | 暫不使用 |
| 右左 | 聚集 | 暫不使用 |
| 上下 | 待定 | 暫不使用 |
| 下上 | 待定 | 暫不使用 |
| 上右下左 | 待定 | 暫不使用 |

### 4.2 輸入語意與法術效果

符文的語意是全遊戲共通的，但符文在不同法術節點上可以導向不同的完整法術。例如：
- 「前進」不必永遠生成相同形態的火焰。
- 「穩定」不代表單純增加持續時間。
- 「提升／強化」不一定只增加傷害。

具體結果由法術圖譜定義，而不是由符文本身直接計算。

### 4.3 輸入判定

第一版採用明確的方向鍵序列：上上、下下、左左、右右，各自是兩次獨立的同方向輸入。輸入時間限制、錯誤序列的處理與視覺提示，先以容易測試為原則實作，之後再調整。

## 5. Fire Spell Graph

### 5.1 第一版節點

| 法術節點 | 輸入路徑 | 初步定位 |
|---|---|---|
| Basic：火球術 | 起始節點 | 直接的遠程攻擊 |
| 火雨術 | 火球術 → 上上 | 範圍持續攻擊 |
| 火焰護盾 | 火球術 → 左左 | 自身防護 |
| 火焰撤離 | 火焰地面 → 左左 | 自身向後閃現一個距離，並在地上留下火焰軌跡 |
| 火焰箭 | 火球術 → 右右 | 快速、集中的直線攻擊 |
| 火焰地面 | 火球術 → 下下 | 在身前創造一片持續燃燒的火焰地板 |
| 火牆術（射出型） | 火焰箭 → 下下 / 火焰地面 → 右右 | 射出一道火牆，造成 dot 傷害 |

以上法術定位是原型的初步假設，並非全部已經定案。

### 5.2 節點規則

- 每個節點代表一個獨立、完整的法術。
- 節點可以透過不同符文路徑抵達。
- 玩家可以在任何有效節點施放法術。
- 法術圖譜只定義允許的節點轉換。
- 同一種符文在不同節點上，可以導向不同的法術。
- 不存在有效轉換的輸入，不應任意生成新的法術。

### 5.3 Prototype 圖譜

```
                        上上
                   ┌─────────────┐
                   │             ▼
              [火球術] ──────> [火雨術]
                  │
         ┌────────┼─────────────┐
         │        │             │
       左左      下下           右右
         │        │             │
         ▼        ▼             ▼
    [火焰護盾] [火焰地面]     [火焰箭]
              │        │             │
            左左      右右           下下
              │        │             │
              ▼        └──────┬──────┘
         [火焰撤離]            ▼
                      [火牆術（射出型）]
```

圖譜中的每個方框都是一個可施放法術，而非單純的法術強化狀態。

## 6. Spell Behaviors

每個節點都需要具備明確的戰鬥行為。第一版不需要精細平衡，但不同法術必須有可辨識的用途。

### 6.1 Basic：火球術
類型：直線投射物。用途：基本遠程攻擊。效果：射出一發投射物，在撞擊敵人或是達到最大距離之後爆開，造成小型範圍傷害。特點：操作簡單、施放直接。原型驗證：作為其他火系法術的起始節點，是否容易理解與使用。

### 6.2 火雨術
類型：範圍攻擊。用途：攻擊一定區域內的敵人。效果：從天空中降下火雨，持續一定時間。原型驗證：與直接火球相比，是否值得花費額外專注值演化。

### 6.3 火焰護盾
類型：自身防護。用途：在危險情況下提供防護。效果：增加自身的防禦力，並對攻擊自己的敵人造成火焰傷害。原型驗證：是否讓玩家在接近 Boss 或預判攻擊時有不同選擇。

### 6.4 火焰撤離
類型：位移技能。用途：向後撤離一段距離，並在地上留下火焰地面。原型驗證：提供逃跑手段。

### 6.5 火焰箭
類型：直線投射物。用途：快速、集中的遠程攻擊。效果：向前射出一束火焰箭，穿透路徑上所有敵人。原型驗證：是否在速度、命中方式或攻擊節奏上與基礎火球形成差異。

### 6.6 火焰地面
類型：持續區域效果。用途：控制地面空間，持續威脅經過或停留的敵人。效果：在地上產生會造成持續傷害的 dot 地面。原型驗證：玩家是否會因 Boss 的位置與移動模式而選擇它。

### 6.7 火牆術（射出型）
類型：射出型火牆。用途：在指定方向具有一定寬度的火焰攻擊。效果：在角色前方創造出射出型的火牆，對火牆中/穿過火牆的人造成 dot 傷害。原型驗證：與火焰地面及火焰箭相比，是否有不同的使用時機與戰術價值。火牆術的具體生成方式、飛行方式與命中判定，仍需進一步定義。

## 7. Focus Resource

### 7.1 基本規則
- 專注值使用連續數值，而非離散次數。
- 進入專注狀態後開始消耗，退出後停止消耗。
- 專注值上限與恢復方式待定，第一版先採用固定消耗速率，方便測試。
- 專注值耗盡時，暫定自動施放目前的有效法術。

### 7.2 Prototype 的調整參數

以下數值全部視為可調整的測試參數，而非最終平衡：專注值最大值、每秒消耗量、Bullet Time 的世界減速比例、專注值恢復速度、法術施放後是否立即恢復正常時間、專注值耗盡時的處理方式。第一版不需要複雜的資源恢復機制，先確認專注值是否真的影響玩家的選擇。

## 8. Basic Combat

### 8.1 普通攻擊
左鍵觸發三連段，不需要進入專注狀態，提供穩定的近距離戰鬥方式。

### 8.2 蓄力火球
一般狀態下透過左鍵蓄力與施放，不需要進入專注狀態，提供簡單、直接的遠程攻擊方式。

### 8.3 戰鬥節奏
基本攻擊與符文施法必須互相補足。基本攻擊讓玩家在一般時間流速下維持戰鬥節奏；符文施法則讓玩家在需要特殊攻擊方式時投入專注值，改變法術形態。

## 9. Test Enemy / Boss

第一版只需要一個能驗證不同法術價值的簡單敵人，建議先具備：一般移動與追擊、近距離攻擊、有明確前搖的強力攻擊、短暫的攻擊間隙、能夠被範圍法術與投射物攻擊的判定。Boss 不需要複雜的階段轉換，重點是讓不同法術有不同的適用情境，例如：Boss 正在遠距離移動時測試直線投射物、Boss 即將進入某個區域時測試火焰地面、Boss 即將攻擊玩家時測試火焰護盾、Boss 停留在某個位置時測試火雨術。這些只是測試情境，最終應依各法術的實際行為調整。

## 10. UI / Feedback

玩家需要隨時理解目前法術狀態。第一版至少需要：目前法術名稱與圖示、專注值顯示、專注狀態的明確視覺提示、Bullet Time 啟動與結束的視覺回饋、符文輸入的確認回饋、有效與無效節點轉換的辨識、當前法術圖譜的簡單提示。不必一開始就呈現整張完整圖譜，優先確保玩家知道目前在哪個節點、輸入後發生什麼變化，以及接下來可以做什麼。

## 11. Prototype Acceptance Criteria

原型完成的標準不是內容數量，而是以下功能可以實際運作：
- 玩家可以在一般狀態下使用普通攻擊與蓄力火球。
- 玩家可以使用右鍵進入與退出專注狀態。
- 進入專注狀態後，世界時間減慢且專注值持續消耗。
- 玩家可以透過方向輸入觸發符文。
- 符文可以依照法術圖譜改變目前法術節點。
- 玩家可以在任何有效節點施放法術。
- 同一個節點可以透過不同路徑抵達。
- 不同法術節點具有可辨識的行為差異。
- 玩家可以透過基本攻擊與符文施法完成戰鬥。
- 專注值耗盡與手動退出專注狀態的行為符合預期。

## 12. Out of Scope

第一版暫時不處理：冰/雷/混沌等其他元素、完整的九種符文效果與所有可能路徑、裝備/掉落/稀有度與 Build 系統、大型關卡與多個 Boss、複雜的角色成長系統、隨機生成法術、完整的故事與任務系統。

## 13. Prototype Development Order

- **Phase 1：核心操作**——完成玩家移動、普通攻擊、蓄力火球、右鍵專注與左鍵施法。
- **Phase 2：符文與圖譜**——實作方向輸入、符文判定、節點轉換，以及目前法術的 UI 顯示。
- **Phase 3：火系法術**——先實作基礎火球、火焰箭、火焰地面與火雨術，確保不同類型的法術能完整運作，再加入其他節點。
- **Phase 4：專注值與 Bullet Time**——加入持續消耗的專注值、世界減速、手動退出與資源耗盡處理。
- **Phase 5：戰鬥驗證**——加入簡單 Boss，測試不同法術在不同情境下的價值，調整輸入時間、資源消耗與施法節奏。
- **Phase 6：補齊火系圖譜**——根據前面的測試結果，再加入火焰護盾、火焰撤離、火牆術，以及其他需要的節點。

## 14. Core Principle

這個 Prototype 的目標，是驗證一套共通的符文語意如何作用於獨立的法術節點，並讓玩家在有限的專注值下，即時選擇法術演化路徑與施放時機。先確保少量火系法術真的能帶來不同的戰術選擇，再擴充完整圖譜、其他元素與裝備系統。
