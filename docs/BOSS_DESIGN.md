# Demo Boss 設計文件

> Demo boss（墮落法師）的行動機制規格。閱讀前請先讀過 `DESIGN.md`（超魔專長序列輸入系統、法術格系統），了解玩家這邊的工具箱。技術細節（檔案、函式、變數名）夾雜在各節裡，給要動手改程式的人用。

---

## 1. 設計定位

這隻 boss 把 PoC 核心機制（吟唱中打超魔專長序列）放進一個有主動威脅、有節奏起伏的戰鬥情境裡測試，對應四個設計問題：

1. **威脅辨識**：場上同時有多個外觀一模一樣的個體時，玩家能不能在壓力下正確分配注意力？（分身誤導機制）
2. **讀技預判**：面對有明確前搖、但命中判定鎖定過去某一刻狀態的攻擊，玩家是否能靠「讀」而不是靠「反射」來迴避？（火球雨／光球連擊的位置鎖定設計）
3. **純粹的遠程對決**：場地分成內圈玩家場地＋外圈 boss 環道，中間隔一圈縫隙，玩家跟 boss 物理上永遠碰不到面，戰鬥是純粹的隔空法術對轟——玩家不能靠欺身打斷讀氣，所有壓力都來自「讀」對方的招式跟自己的走位/瞄準。
4. **風險調度**：當場上有威脅在跑，玩家仍要不要冒險打出高風險的長序列超魔專長？

**血量/死亡系統現況**：HP 歸零直接重置滿血＋閃光，不是真正的死亡，跟結算畫面完全無關。分身是唯一例外——分身的 3 HP 歸零是真的會消失，因為「可以被擊殺」是誤導機制成立的必要條件。

---

## 2. 外觀與定位

視覺定位是玩家法師的「墮落鏡像」：同一套法師輪廓（長袍、披風、正面臉），紅色系取代玩家的紫色系，比例是玩家的 1.5 倍。造型不畫帽子，光靠紅袍＋披風＋正面臉跟玩家的紫袍區分開。腳下有陰影＋一截露出來的腿，陰影跟腿之間刻意留一點空隙不相連，製造角色微微懸空的感覺。

招式全部是魔法攻擊（火球雨、光球連擊、吸引懲罰），沒有任何近戰招式——boss 物理上只能待在外圈環道，玩家物理上只能待在內圈場地，不是靠 AI 選擇要不要拉開距離，是場地規則直接鎖定。

---

## 3. 場地佈局

場地（`Arena.gd`）是三個同心圓區域，由內而外：

| 區域 | 半徑/範圍 | 說明 |
|---|---|---|
| 玩家場地 | `PLAYER_ZONE_RADIUS` = 260 | 玩家唯一能站的地方，`Main.tscn` 的牆壁碰撞（`Walls/Boundary`）圍這一圈，物理碰撞實際擋住 |
| 縫隙 | 寬度 `GAP_WIDTH` = 100 | 完全淨空，不鋪地磚、沒有牆面裝飾——兩個場地「不能互通」的來源 |
| boss 環道 | 內緣 `BOSS_RING_INNER_RADIUS` = 360（= `PLAYER_ZONE_RADIUS + GAP_WIDTH`），外緣 `ARENA_RADIUS` = 450，環道寬度 90 | boss 跟所有分身唯一出現的地方 |
| boss 巡邏軌道半徑 | `BOSS_TRACK_RADIUS` = 405（= 環道內外緣正中點，公式算出來） | boss 實際巡邏的固定半徑 |

牆體厚度 `WALL_THICKNESS` = 24。`Arena.gd` 畫三道同心圓弧牆（玩家場地外牆、boss 環道內牆、boss 環道外牆），各自有內緣亮/外緣暗的浮雕邊模擬牆有高度。地磚生成分別處理內圈圓盤跟外圈環帶兩塊區域，縫隙範圍內的格子不產生。

boss/分身不走物理碰撞（手動控制位置，`collision_mask=0`），靠 `_clamp_to_arena()` 把位置夾在 `[BOSS_RING_INNER_RADIUS, ARENA_RADIUS]` 之間維持在環道內（正常巡邏不會觸發這個夾限，主要防止被玩家法術擊退後飄出環道）。

**法術完全不受縫隙阻擋**：投射物/AoE 沒有牆壁碰撞，縫隙對它們只是飛過去的空間。`LightningBolt`（雷電箭）的撞牆反彈例外——它是玩家法術，反彈邊界用 `PLAYER_ZONE_RADIUS`（玩家自己的場地邊界），不是 `ARENA_RADIUS`，否則會飛穿縫隙跑進 boss 環道裡彈。

**玩家法術射程**：`ForceWave`（力場波，半徑140）貼牆時觸及 260+140=400，跟 `BOSS_TRACK_RADIUS`（405）只差5，實務上難以構到 boss。`Fireball`（射程500）/`LightningBolt`（路徑總長1800）射程足夠，不受影響。

## 4. 走位：固定軌道巡邏

boss 跟分身沿外圈固定軌道巡邏，完全不理會玩家在哪。位置公式：

```
位置 = ARENA_CENTER + 方向(track_angle) × BOSS_TRACK_RADIUS
```

不管有沒有分身，本體跟每個分身都適用同一條規則（分身跟本體錯開角度、等分站位站在同一條環道上）。

**巡邏節奏是「停頓→快速跳位→停頓」，不是連續勻速繞圈**（`_process_patrol()`）：

| 數值 | 現行值 | 說明 |
|---|---|---|
| 跳位間停頓時間 | `PATROL_PAUSE_TIME` = 0.9 秒 | 每多一個分身疊加 `SPEED_PER_CLONE`（0.1）縮短，4隻分身滿編時縮短到 -40% |
| 單次跳位角度 | `PATROL_MOVE_ANGLE` = 80° | 連跳9次會繞完2圈、踩過環道上9個等分點才回到起點（{9/2}星形路徑），不是依序繞相鄰點，不好預判下一步落點 |
| 單次跳位動畫時間 | `PATROL_MOVE_TIME` = 0.22 秒 | 用 ease-out 立方插值（快速衝出去、尾段收斂），不是等速直線移動；不受分身數量影響 |

施法（前搖/連發/讀氣）期間巡邏會停下，用 `is_wandering` 統一開關——關閉時 `_process_patrol()` 整個不會被呼叫，停頓/跳位計時器原地凍結，恢復巡邏時從凍結進度接著走，不會重置或跳到隨機新位置。

分身的巡邏角度是「本體角度 + 固定偏移」，每幀由本體的 `_sync_clone_formation()` 同步寫入，分身自己不需要維護任何計時狀態——本體的停頓/跳位節奏會自動反映到所有分身身上。

## 5. 分身誤導（Decoy Clones）

**目的**：場上有多個外觀一致的個體，玩家無法單靠視覺辨認真身，必須用記憶/賭注應對；威脅密度隨分身數量持續攀升，逼玩家不能無限期拖延清分身。

| 數值 | 現行值 | 說明 |
|---|---|---|
| 分身上限 | `CLONE_MAX` = 4（分身數量，不含本體） | 連本體一起算，場上最多同時有 5 個會行動的個體 |
| 每批新增 | `CLONE_SUMMON_BATCH` = 2 | 逐批累加到上限，不是一次補滿 |
| 分身 HP | `CLONE_HP` = 3 | 遠低於本體的 200，刻意好打，但玩家無法從外觀分辨誰是分身 |
| 讀氣時間 | `CLONE_SUMMON_CHANNEL` = 4 秒 | 讀完才生出新一批 |
| 讀氣中斷門檻 | `CLONE_SUMMON_INTERRUPT_THRESHOLD` = 10 點傷害 | 累積到就中斷，CD 重算 |
| 分身術 CD | `CLONE_SUMMON_CD` = 5 秒 | 每次分身術施放完就重算 |
| 開場保護期 | `CLONE_SUMMON_OPENING_GRACE` = 15 秒 | 開場這段時間完全不能放分身術 |

分身存活時，陣型自動維持「總人數等分 360°」的巡邏站位，沿 boss 環道分散（不是圍著玩家——玩家物理上搆不到，圍著玩家站沒有意義），分身死掉或新增時自動重新對齊。新分身一出生就直接定位在陣位上，不會先生在本體旁邊再移動過去。

本體讀氣召喚新分身期間，既有分身會停下來並一起亮起跟本體一模一樣的讀氣光環（進度同步）——分身本身沒有真的做任何事，只有本體真的在倒數讀氣、真的會生出新分身，分身的光環純粹是視覺上的同步演出。

分身術永遠優先於週期招式：閒置中（`IDLE`）分身術一轉好就立刻插隊；週期招式執行中轉好的話，等招式完全結束、再等 `CLONE_READY_BUFFER`（1秒）緩衝才開始讀氣。

## 6. 週期招式

`ATTACK_CD` = 7 秒，進入 `IDLE` 時 `next_attack` 50/50 隨機決定下一招是火球雨還是光球連擊。

### 6.1 火球雨

命中判定在丟出的瞬間鎖定玩家當時所在的地板座標，之後不管玩家怎麼移動都不會再更新——玩家只要在丟出瞬間所在的位置離開，之後全程走位自由，不會被追蹤彈懲罰。

| 數值 | 現行值 |
|---|---|
| 前搖時間 | `FIREBALL_TELEGRAPH_DELAY` = 0.5 秒 |
| 爆炸半徑（橢圓判定） | `IMPACT_RADIUS` = 95 |
| 傷害 | `FIREBALL_DAMAGE` = 10 |

每個施法者（本體跟存活分身各自獨立）頭上先出現預告圖案，丟出瞬間鎖定座標，之後整段飛行畫面上完整顯示爆炸範圍圈，飛到鎖定距離就地面爆炸，沒有落地延遲。**有分身時嚴格依序發射**：等上一顆爆炸完，下一個分身才會丟，不是同時丟出。

### 6.2 光球連擊

每個施法者向玩家當時位置丟出方向鎖定（丟出瞬間鎖定，之後不追蹤）的光球，連續丟 `ORB_COUNT`（3）顆。

| 數值 | 現行值 |
|---|---|
| 連發間隔 | `ORB_THROW_INTERVAL` = 0.3 秒 |
| 施法者錯開時間 | `ORB_CASTER_STAGGER` = 0.25 秒 |
| 起始速度／加速度 | 220 px/s ／ 500 px/s²（持續加速，不是固定速度） |
| 傷害 | `ORB_DAMAGE` = 12 |
| 命中判定半徑 | 26 |

撞到場地邊界直接消失，沒有反彈。**有分身時「錯開起跑、各自獨立連發」**：第一個施法者立刻開始丟自己的3連發，隔 `ORB_CASTER_STAGGER` 秒後下一個施法者才開始丟自己的連發（不等前一個丟完），每個人的節奏彼此獨立並行。

## 7. 吸引懲罰（目前停用）

> **現況：`Boss.SUCTION_ENABLED = false`**。邏輯完整保留在程式碼裡，只是觸發判定那一步被擋住，不會真的出招。

機制本身：不是跟火球雨/光球連擊並列的週期招式選項，是玩家欺身過近時的個體反射動作。本體跟每個分身持續監控自己跟玩家的距離，進入 `SUCTION_TRIGGER_RANGE`（170px）後**機率隨距離線性遞增**觸發（貼到0距離時機率密度最高，剛踏進邊緣時趨近0），每個施法者各自獨立骰，不是只看最近的一位。

骰中的施法者展開 narrow 扇形（半張角 `SUCTION_HALF_ANGLE`≈20°，共40°張角；射程 `SUCTION_RANGE`=200）鎖定玩家方向，`SUCTION_TELEGRAPH_DELAY`（0.4秒）預警後開始持續拉扯玩家（`SUCTION_PULL_SPEED`=100px/s）並把移動速度打五折（`SUCTION_SLOW`=0.5）。玩家被拉到 `SUCTION_CLOSE_RANGE`（70px）以內時，立刻觸發一次性大傷害（`SUCTION_BURST_DAMAGE`=25）並往施法者反方向擊退（`SUCTION_KNOCKBACK_DISTANCE`=260px，用運動學公式反推初速，是一段有過程的推開動畫，不是瞬移）。玩家連續 `SUCTION_EARLY_CANCEL_WINDOW`（0.5秒）沒被扇形咬住就提前取消；完全沒觸發也沒取消則撐滿 `SUCTION_DURATION`（3秒）自然結束。

---

## 8. 隱形術對 boss 的影響

玩家隱形時，`_find_player()` 回傳 `null`，等於 boss 找不到玩家。這個函式是本體/分身鎖定玩家位置的唯一入口（火球雨丟出瞬間、光球連擊的方向、吸引懲罰的距離判定都經過它），單點擋住就讓所有攻擊同時失去目標。已鎖定飛行中的攻擊不受影響（隱形防的是新的鎖定，不會回溯擋掉已經飛出去的攻擊）。

| `scripts/entities/boss/BossFireball.gd` | 火球雨單顆火球：`TELEGRAPH`→`FLYING` 兩階段，命中判定鎖定丟出瞬間的玩家座標 |
| `scripts/entities/boss/BossOrb.gd` | 光球連擊單顆光球：直線加速飛行，方向鎖定丟出瞬間，撞牆直接消失 |
| `scripts/entities/boss/BossSuctionZone.gd` | 吸引懲罰的單一扇形範圍：`TELEGRAPH`→`ACTIVE` 兩階段，永遠只服務一個施法者 |
| `scenes/entities/boss/*.tscn` | 對應場景：`Boss`/`BossClone` 是 `StaticBody2D`＋`CircleShape2D`（碰撞半徑30），`BossFireball`/`BossOrb`/`BossSuctionZone` 是純 `Node2D` |
| `scripts/core/Arena.gd` | 場地三層同心圓結構，`PLAYER_ZONE_RADIUS`/`GAP_WIDTH`/`BOSS_RING_INNER_RADIUS`/`BOSS_TRACK_RADIUS`/`ARENA_RADIUS` |

**怪物招式不走 `Spell`/`SpellDelivery`/`SpellEffect` 架構**——那套是為「玩家可配置、可替換」設計的，boss 招式是固定寫死的行為，直接寫在怪物腳本裡，不會出現在 `GameState.CATALOG` 裡。

**視覺共用、程式碼各自一份**：`Boss`/`BossClone` 要看起來完全一樣，靠 `Boss.gd` 的 `static func _draw_boss_body(node, ...)` 共用畫法，兩邊的 `_draw()` 都呼叫它。`BossClone.gd` 沒有自己的 AI/狀態機，純粹是本體的執行端；`_find_player()` 在 `Boss.gd`/`BossFireball.gd`/`BossOrb.gd`/`BossSuctionZone.gd` 四個檔案裡各自複製一份，不是共用函式呼叫——行為共用但程式碼各自一份是這個檔案群組的既有慣例。

## 11. 已知限制

- **沒有真正的死亡/結算**：HP 歸零重置滿血＋閃光，是佔位行為。
- **沒有攻擊造成的吟唱中斷**：所有傷害來源只扣血/視覺回饋，不會打斷玩家正在進行的超魔專長吟唱。
- **減速是單一數值修飾，不是通用 buff 系統**：`Player.gd` 的 `speed_multiplier` 由施加效果的一方（這隻 boss）直接讀寫，不是「目前生效中的效果清單」這種通用架構——只有一個減速來源時沒問題，但兩個獨立減速來源會互相覆蓋而不是疊加。
- **只有一種怪物**：分身術會讓場上同時有多個會行動的個體，但都是同一隻 boss 的分身，不是多種不同怪物同時戰鬥。
- **boss 身上的擊退效果視覺上幾乎看不出來**：boss 位置每幀都由 `track_angle` 重新算出來，`apply_knockback()` 機制還留著（`ForceWave` 擊退打中 boss 一樣會呼叫），但視覺上只會閃現一瞬間就被下一幀的巡邏公式蓋掉。傷害判定不受影響。
- **`ForceWave` 難以構到 boss**：場地內外圈隔開後，只有玩家貼著自己場地的牆、且 boss 剛好巡邏到環道內緣附近時才碰得到，不是每次都打得到。
